# 狀態檔改放 ~/.omnikit

日期：2026-11-18。狀態：已採用，實作在 `engine/scripts/statedir.py`。

## 要解決的事

OmniKit 原本把狀態放在 `%LOCALAPPDATA%\omnikit`。Claude 桌面版是 MSIX 封裝的 app，從它的對話裡跑 OmniKit 時，在 AppData 新建的檔會被 Windows 轉存到 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\omnikit`。結果封裝內外各看到一份：

- home_watch 在兩邊各跑各的。
- 從終端機跑 `uninstall.ps1` 找不到封裝裡的 `install-record.json`。這台改之前，安裝紀錄確實只在封裝那份。
- doctor 的結果要看是從哪裡跑的。

ryan 的要求：以後在任何電腦首次安裝 OmniKit，都要能直接適配任何環境。

## 在這台實測的規則（Windows 11 26200）

| 情況 | 結果 |
|---|---|
| 封裝內讀 `%LOCALAPPDATA%\omnikit` | 看到的是合併視圖；同名的檔以封裝副本那份為準 |
| 封裝內新建頂層資料夾（例如 `%LOCALAPPDATA%\新資料夾`） | 寫進封裝副本，封裝外看不到 |
| 封裝內在「只在真實位置存在」的資料夾裡新建、修改、刪除 | 直接作用在真實位置 |
| 封裝內寫家目錄（`%USERPROFILE%`，AppData 以外） | 不轉存，封裝內外是同一份 |
| 封裝內先把封裝副本搬走 | 之後看到的就是真實那份，所以從封裝內也能把兩份完整合併 |
| `GetCurrentPackageFullName` | 在 Claude 桌面版的子程序回傳 15700（沒有封裝身分），不能拿來判斷自己在不在封裝裡 |
| 用 WMI（`Win32_Process.Create`）開程序 | 會在封裝外，可以拿來驗證；但它對應 MITRE ATT&CK T1047，容易被防毒或 EDR 擋，只用在測試，不放進產品程式碼 |

微軟的說明（[Understanding how packaged desktop apps run on Windows](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)、[Flexible virtualization](https://learn.microsoft.com/en-us/windows/msix/desktop/flexible-virtualization)）也這麼寫：Windows 10 1903 以後，AppData 底下新建的檔會轉存，既有的檔可以原地修改；只有封裝 app 自己的 manifest 能排除目錄。Claude 桌面版的 manifest 只排除了自己的 4 個資料夾。同一個症狀已經有人回報給上游：[anthropics/claude-code#93152](https://github.com/anthropics/claude-code/issues/93152)、[openai/codex#41665](https://github.com/openai/codex/issues/41665)、[openai/codex#55241](https://github.com/openai/codex/issues/55241)，這次查的時候都還是 OPEN。

## 方案比較

| 方案 | 做法 | 新電腦首次安裝 | 代價 | 決定 |
|---|---|---|---|---|
| A. 改放家目錄 | 狀態放 `~/.omnikit`，環境變數 `OMNIKIT_STATE_DIR` 可以改；舊位置合併過來 | 不挑是從哪個 app 跑的，以後多了別的封裝 app 也沒差 | 要寫一次合併；家目錄多一個點開頭的資料夾 | **採用** |
| B. 跳出封裝 | 偵測到在封裝裡，就用 WMI、`schtasks` 這類方法開封裝外的程序去寫 | 偵測本身就不可靠（上面那個 15700）；企業電腦的 EDR 常擋 | 拿不到 stdout，要另外接；每個子指令都要包一層 | 不採用 |
| C. 請上游改 manifest | Claude、Codex 把 OmniKit 的資料夾排除 | 不在我們手上，而且每個封裝 app 都要改一次 | 只能等 | 不採用（上游 issue 已經有人回報） |
| D. 留在 AppData，兩份一直同步 | 每次讀寫都比對兩份 | 每多一個封裝 app 就多一份 | 複雜，容易出錯 | 不採用 |

同類工具的做法：Claude Code（`~/.claude`）、Codex（`~/.codex`）、Gemini CLI（`~/.gemini`）、T3 Code（`~/.t3`）、cargo（`~/.cargo`）、Git（`~/.gitconfig`）都放家目錄，所以不受影響。放在 AppData 的 uv、pipx、npm、gh，在封裝的 app 裡跑就會分成兩份；uv 在 Claude 桌面版裡已經有人遇到。

## 合併的做法

`statedir.migrate` 在 `agents.py`（status 以外的指令）、`profiles.py`、`install.ps1`、`uninstall.ps1`、git hook 的 `sync-data.sh` 開頭執行；home_watch 開新對話時發現舊位置還有東西，就在背景跑 `agents.py sync`（6 小時內不重跑）。

1. 找舊位置：每個 `%LOCALAPPDATA%\Packages\*\LocalCache\Local\omnikit`，最後才是 `%LOCALAPPDATA%\omnikit`。封裝副本要先搬：搬走之後，封裝內看到的 `%LOCALAPPDATA%\omnikit` 才是真實那份。
2. 整個搬進 `~/.omnikit/legacy/<時間>/<來源>/` 備份。搬不動就複製，並在 `migrate.json` 記下當時每個檔的大小與時間，下次只算之後多出來的。
3. 合併：
   - 內容一樣的只留一份。
   - `.jsonl`、`.log`：每一行都留，去掉重複的；`.jsonl` 照 `ts` 排序。
   - `.json`：以較新的那份為準，缺的鍵補上；字串清單取聯集；純值不一樣就列成衝突。
   - 其他檔取較新的那份，列成衝突。
   - git repo（例如狀態 repo `status`）整塊處理：選最近有動靜的那份；另一份有沒 push 的 commit 就列出來。
   - junction、symlink 不跟進去，列出來。
4. 用鎖檔 `.migrate.lock` 防止重複執行，超過 600 秒當作上次當掉。
5. doctor 回報還沒合併的舊位置（失敗），以及上次合併的衝突（附備份位置）。

## 驗收（這台，2026-11-18）

- 從桌面版對話裡跑 `agents.py sync`：搬了封裝副本 418 個檔、`%LOCALAPPDATA%\omnikit` 60 個檔，合併 207 個檔，列出 4 處衝突（edition.json 的日期、home_watch.json 的兩個欄位、rules/AGENTS.md）。狀態 repo 搬過來後 `git status` 是乾淨的，跟 origin 同步。
- 之後從桌面版對話裡、以及用 WMI 開的封裝外程序，各跑一次 `agents.py status`、`doctor.py`、`statedir.py status`，三份輸出逐字相同（164 行、110 行、2 行）；兩邊看到的舊位置都不在了，`install-record.json` 的 SHA-256 相同。
- 封裝外用非互動方式跑 `uninstall.ps1`，預覽列出 npm 套件、兩個工具資料夾、權限規則與三個設定目錄的 hook，沒有「找不到安裝紀錄」的警告。
- 測試：`statedir.py --selftest`（Python 3.11 與預設版本，含 junction）、`windows-ci.ps1` 加上舊位置與封裝副本的合併檢查。
