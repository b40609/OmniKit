# OmniKit 方向討論總結（2026-11-16 到 11-17）

這一頁是幾輪討論的統整，只看這頁就夠。細節在兩份文件：[產品邏輯檢討](2026-11-16-product-logic-review.md)（為什麼原本的方向不成立）與[方向修訂](2026-11-17-guide-and-playbook.md)（新方向的依據與數字）。

## 1. 一句話

OmniKit 不再當「工具組合顧問」（建議裝什麼、拿掉什麼、出週報），改成**幫你和同事把 coding agent 用好的一包東西**：設定引導、問法庫與官方功能對照、當下提醒，加上交接、分派、調研、實測這幾個工作流。

## 2. 為什麼改

- **官方已經做了「量」的部分，而且做得比外掛好。** Claude Code 的 `/doctor`、`/skill-doctor`、`/usage`、`/insights` 涵蓋沒在用的工具、context 成本、使用習慣。在這台實跑，`/doctor` 涵蓋了 OmniKit 建議的全部範圍。
- **OmniKit 自己的使用紀錄也這樣說。** 7 天內叫用最多的是交接（12 次，一份 20 行的說明）；建議與週報背後約 7,600 行程式，叫用 1 次。換與換回 0 次有效使用。
- **槓桿在習慣，不在工具清單。** 這台 7 天的用量有六成是重送舊對話；47 個沒叫用的 skill 加起來才約 5,870 tokens。
- **你說少了會失望的**（2026-11-17）：壓縮與交接、分派、規則的引導設定；新電腦的起手清單；使用技巧與問法。沒有一項是建議、週報、換與換回。

## 3. 四個原則

1. **要量的交給官方，要寫的自己留。** 偵測與統計是 harness 的強項；你們的規則、約定、問法、實測結論，官方不會知道。
2. **內容跨 agent，讀紀錄不跨。** 規則檔、skill、問法都是 Markdown，三家都能用。解析各家對話紀錄的程式貴而且一直壞。
3. **先有使用再蓋引擎。** 先手動做兩輪，確定有人用才自動化。
4. **沒實測過不給同事。** 先在你身上驗證。

## 4. OmniKit 的新樣子

| 部分 | 做什麼 | 現況 |
|---|---|---|
| 規則與設定引導 | 底線、個人規則、分派；一次問答把該設的設好（語言、訂了哪幾家、精簡輸出、壓縮門檻） | 已做。設定問答加了三項（`omnikit-setup` 第 4b 節）；分派的常駐規則縮成幾行，完整政策要派才讀。新增的三項還沒有找人實際走過一遍 |
| 問法庫與官方功能對照（`omnikit-ask`） | 卡住時依情境給問法與做法；告訴你該用哪個官方功能、三家各怎麼用 | 第 0 版已做：72 個情境、一張對照表。這台用預設模型試 3 題都有叫用（Haiku 是 3 題 2 題）。還沒有對照實測 |
| 當下提醒 | 事情發生時講一句：該開新對話、該交接、官方功能的用法小提示、該跑 `/insights` | 已做。小提示在 `data/tips.json`（9 則，一天最多一則、每則一次）；`/insights` 超過 14 天沒跑，在第一次 push 時提醒 |
| 工作流 | 交接、分派、調研、實測 | 都有，照常用 |
| 官方功能雷達 | 盯三家的更新紀錄，更新對照表，並指出哪些已裝的工具被取代了 | 手動做了兩輪（11-17 第二輪補齊 Codex、Antigravity 欄，加 3 則小提示）；自動更新要接 OmniKeep，還沒做 |
| 起手清單 | 人人都要的設定、實測過值得裝、實測過不用裝、還沒測、已被官方取代 | 已做：`docs/starter.md` |

建議、週報、換與換回、工具通知、成本報告、回流：**2026-11-17 已停用**（`omnikit-weekly` 不再自動觸發，對話開頭不再附工具通知；腳本約 7,600 行還留著，確認沒人用再刪）。之後要拿掉的還有：自製的安裝與移除（約 3,000 行，先做原生 plugin 的原型確認能取代）；解析 Codex 紀錄的部分。

## 7. 接下來的順序

1. **你**：在筆電與家裡電腦實測問法庫，照 `data/pilot/ask-test.md` 記錄。這是目前唯一卡在你身上的事。
2. 對照表與小提示每兩週手動更新一次，下一次約 2026-12-01。兩輪已做完（11-17）；12-01 那輪做完還有用，再提接 OmniKeep 自動化（要在 OmniKeep 專案另開對話）。
3. 凍結結束（11-29）後：在現有 marketplace 加 `omnikit` plugin，取代 `agents.py` 接 skill、MCP、hook 的部分，`install.ps1` 縮成只做 plugin 帶不了的事。原型的結論與要照做的事在上面那份 review。拿掉舊程式前會先問。
4. 可以先做的：用 `claude plugin eval` 替問法庫跑「有它與沒它」的對照（它會自動加沒裝 plugin 的對照組），補上 agent 能自己量的那一半。
5. 確認兩週沒人用之後，刪掉停用的腳本（約 7,600 行）。刪除前會先問。

日期固定的：2026-11-29 凍結結束；2026-11-30 看分派統計、Exa 試用到期。

## 9. 還沒驗證的（重要的幾項）

- 問法庫 72 條沒有任何一條做過「有它與沒它」的比較。
- 我從這段對話裡啟動的無頭 Claude 都跑在 Haiku 5.5，不是你的預設模型（桌面版的環境變數被繼承了）。所以 11-17 的 `/insights`、`/team-onboarding` 是 Haiku 產生的；11-16 的 `/doctor`、`/skill-doctor` 用同樣的方式啟動，很可能也是。內容我讀過、對得上實況，但用你平常的模型跑，結果可能更好。
- 壓縮門檻省兩成是模擬的上限，不是實測。
- Codex 與 Antigravity 上，問法庫會不會被叫用沒試過；Antigravity 的官方指令沒查到文件。
- T3 開的 Claude 對話吃不吃 400k 這個設定，沒驗證。
- 今天加的當下提醒只用假的對話紀錄測過（自我測試加一次端到端），還沒在真的對話裡看到它出現。
- 設定問答新增的三項是寫給 agent 照做的說明，還沒有人實際走過一遍。
- 原生 plugin：Claude Code 與 Codex 實測能帶 skill、MCP、hook，規則用 hook 注入可行，這次防毒沒擋。還沒測的是 Antigravity、從 GitHub 安裝、沒有 uv 的電腦、權限規則（細節見原型的 review）。
