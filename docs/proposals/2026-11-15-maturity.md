# 從玩具到成熟工具：凍結、收斂、試點、清積壓

日期：2026-11-15。狀態：使用者已同意 A 到 D 四個方向（2026-11-15「照建議全做」）。瘦身已做完；試點等使用者給名單，`dispatch.md` 的 4 個【待確認】等使用者決定。

## 結論

- OmniKit 像玩具，原因不是缺功能，而是**沒有一條流程被真的用熟**。11 天 61 個 commit、約 38 支腳本，影子比對的 4 筆試用紀錄都是 0 段任務，同事沒有裝過。
- 官方已經做掉兩塊：Claude Code 端「哪些沒在用、吃多少 context」（`/plugin` 的 Not used recently 與 Context cost、`/skill-doctor`），以及 Claude Code 端「這個專案該加什麼」（Claude Code Setup）。
- OmniKit 留下官方沒做的四件事：**跨 agent（Codex、Antigravity）、試用與換回加上可比對的證據、名冊的判斷與實測、團隊底線規則與交接**。
- 接下來兩週：凍結功能（A）、把承諾收斂到上面四件（B）、你加 1 到 2 位同事實際用兩週並看 3 個指標（C）、清掉堆著的決定與 11-10 檢視報告的瘦身（D）。

## 起因

使用者 2026-11-15：「我目前覺得還是很像一個玩具，整天沒有成熟工具的感覺（還是有很多缺口）」。另外的瓶頸是開發中一直看到可參考的新東西（`claude-plugins-official`、Claude Code Setup、lobehub），所以一直在改，並覺得 Claude Code Setup「完全可以取代 OmniKit」。

## 官方與業界

讀的是官方文件、官方 repo 原文與搜尋結果；試點的做法多數是廠商文章，不是嚴謹研究。

| 對象 | 做什麼 | 不做什麼 | 來源 |
|---|---|---|---|
| Claude Code Setup（`claude-automation-recommender`） | 讀專案檔，MCP、skill、hook、subagent、plugin 五類各建議 1 到 2 個，附理由；候選來自 5 份內建清單加上網搜尋；唯讀 | 不看實際使用、不建議拿掉或換、只管 Claude Code。frontmatter 只宣告 `Read, Glob, Grep, Bash`，內文卻要求上網搜尋 | `anthropics/claude-plugins-official` 的 `plugins/claude-code-setup`（讀到 `b5b01ac`，2026-11-13） |
| Claude Code `/plugin` | Installed 頁有 Not used recently 分組與 Last used；官方市集的 plugin 顯示 Context cost | 只管 plugin；沒有跨 agent | code.claude.com/docs/en/discover-plugins.md |
| 社群的「找沒在用」工具 | mcp-graveyard、skill-graveyard、mcp-usage、mcp-audit、mcp-checkup：讀對話紀錄找沒用的 MCP 或 skill、量 token 成本 | 都只管 Claude Code；沒有試用、換回、實測 | 各自的套件頁；品質沒驗證 |
| lobehub | 自稱 MCP 約 12 萬、skill 約 36 萬筆 | 沒有公開的目錄 API（`openapi.json` 只有 3 個無關路徑，market API 回 401） | lobehub.com/openapi.json、llms.txt |
| 試點與指標 | 沒有公認的人數或週數；常用的是採用動能（用量成長、持平、下滑）與使用頻率分層；Superhuman 用「少了它會非常失望」的比例找核心族群（基準 40%） | 自願加入的試點數字偏樂觀，不能外推（Jellyfish） | jellyfish.co、getdx.com 的 Grammarly 案例、First Round Review 的 Superhuman 文章（二手摘要） |

同時做跨 agent、試用與換回、實測證據的專案沒有搜到【待驗證：只是沒搜到】。

## 並排比較：Claude Code Setup 與 `report.py advise`（這台，2026-11-15）

Claude Code Setup 用 `claude -p --plugin-dir`（Sonnet）在 OmniKit repo 跑一次；`advise` 用 `uv run engine/skills/omnikit-weekly/scripts/report.py advise`。

| | Claude Code Setup | OmniKit `advise` |
|---|---|---|
| 對象 | 這個專案 | 這個人、這台電腦，Claude Code 與 Codex 各一份 |
| 建議的東西 | 專案層的 hook（改 YAML 後跑 `validate.py`、擋改 `_site/`）、專案 skill（`ci-local`、`bump-rules-version`）、subagent（規則審查、突變測試）、MCP（GitHub、context7）、加專案 `CLAUDE.md`、整理 `settings.local.json` | 使用者層的工具：裝（100 個候選）、拿掉（Claude Code 2 個、Codex 18 個，依 30 天沒用）、用內建的就好（12 個）、規則檔可拿掉的段落（41 段）；換 0 個 |
| 量 | 每類 1 到 2 個，總共約 10 項，直接可讀 | 原始輸出 8,211 行 JSON，要 agent 再挑 |
| 依據 | 專案檔的結構 | 對話紀錄的使用統計、名冊的判斷與實測 |
| 會不會拿掉或換 | 不會 | 會 |

結論：兩者**幾乎不重疊**。Claude Code Setup 管「這個 repo 該加哪些自動化」，OmniKit 管「這個人該留、該拿掉、該換哪些工具」。它不能取代 OmniKit，但 OmniKit 也不該自己做專案層的建議，交給它就好。它給的幾項（改 YAML 後自動跑 `validate.py`、`ci-local`）對這個 repo 本身有用，記進待辦，凍結期間不做。

## 決定

### A. 凍結

- 兩週內（到 2026-11-29）不加新功能、不接新來源。修 bug、瘦身、試點需要的修正不算。
- 看到新的工具或來源，在 `data/inbox.md` 記一行：名稱、網址、哪天看到、可能對應哪個槽位。每週用 `omnikit-eval` 一次看完。

### B. 收斂範圍

| OmniKit 做 | 交給官方或別人 |
|---|---|
| Codex、Antigravity 端的使用統計、規則同步 | Claude Code 端的「沒在用」與 context 成本（`/plugin`、`/skill-doctor`） |
| 試用、換回、影子比對的證據 | 專案層的自動化建議（Claude Code Setup，收進名冊當一張卡） |
| 名冊的判斷與實測（每個槽位在每個 agent 的答案） | 安裝本身（各 agent 原生的 plugin 指令） |
| 團隊底線規則、子任務分派、交接 | 大量目錄的廣度（官方目錄、skills.sh，只當候選池） |

### C. 試點（兩週）

- 人：使用者自己加 1 到 2 位同事。名單由使用者決定。
- 開始前：在同事電腦跑安裝前檢查（`preflight.ps1`），只檢查不寫入。
- 3 個指標：
  1. 每週有沒有實際跑一次「給我建議」或週報（看 `%LOCALAPPDATA%\omnikit\advice\`）。
  2. 建議的採納率（週報已經在算「主動建議的接受率」）。
  3. 兩週後問一次：「少了 OmniKit 會不會非常失望？」（非常、有點、不會）。
- 兩週後依結果決定繼續、縮小或停。
