# 問法庫：有它與沒它的對照評測（agent 自己量的那一半）

日期：2026-11-17。工具：Claude Code 2.1.326 的 `claude plugin eval`，它會替每一題自動加一組「沒裝這個 plugin」的對照。題目與重跑方式在 `data/pilot/ask-eval/`（`pwsh -File data/pilot/ask-eval/run.ps1`）。

## 結論

**有它比較好，而且沒有一題變差。** 11 題的平均分數，有它 0.97、沒它 0.64。差距集中在三種情況：要先盤點或先問清楚的（畫面太雜、需求還沒想清楚）、修過又復發的 bug、問官方功能怎麼用。agent 本來就會的（找別人審、舊程式先補測試、時好時壞的 bug）兩組都滿分，問法庫沒有加分。

這只是一半的答案。它量的是「回覆有沒有照好的做法、有沒有給可以直接貼的句子」，不是「你用起來有沒有少修正幾輪」。後者還是要靠你照 `data/pilot/ask-test.md` 實測。

## 怎麼量的

- 11 題，從 72 條裡挑，涵蓋前端、操作流程、除錯、需求、舊程式、跟 agent 協作、複盤，另加一題問官方功能（`/clear` 與 Codex）。5 題用「我不知道怎麼問」這類觸發語，6 題只描述處境。
- 每題兩組（有 plugin、沒有 plugin）各跑 2 次。模型是這台的預設 `claude-opus-5-5`，評分用 Sonnet，每個評分項投票 3 次。
- 每題兩個評分項：
  - 做法（權重 2）：有沒有照該領域公認的做法，例如「先寫能重現的測試再修」「先盤點入口與使用頻率再合併」。
  - 可以直接貼（權重 1）：有沒有一段針對這個情況、可以直接貼給 agent 的句子。
- 確認過對照組沒有被汙染：對照組的 skill 清單裡沒有 omnikit-ask，也沒有叫用它。使用者層級已裝的那份沒有跑進對照組。

沒它時常見的差別：
- 直接猜原因或給修法，沒有「先寫會失敗的測試」「全專案搜同樣寫法」。
- 先列一串問題要使用者一次回答，而不是一次問一題、附推測。
- `/clear` 那題說得大致對，但 Codex 的指令沒把握；有它時給出 `/new`、`codex resume`，跟官方原始碼一致。
- 很少給可以直接貼的句子。

## 過程中改掉的

- **「重複提醒」那題兩次都沒叫用問法庫。** 在 skill 說明加上「同一件事提醒好幾次想讓它下次自己記得」，重跑 3 次都有叫用、3 次滿分（`SKILL.md`）。這正是實測步驟裡「說了卻沒被叫用就改說明文字」那條規則。
- **兩個題目本身有錯，重跑過：**
  - `/clear` 那題的題目用 `/clear` 開頭，被當成指令直接執行，兩組都沒有回覆。改成「Claude Code 的 /clear 指令是做什麼的」。
  - 「修過又復發」那題的評分標準裡有一句「主要是在猜原因就算失敗」，評分者把順帶的猜測也算進去，有它那組四步都做了仍被判失敗。改成只數四項做了幾項，兩組用同一個新標準重跑。原本的結果是有它 0.33、沒它 0。

## 要打折看的地方

- **評分標準跟問法庫同源。** 「做法」那一項是照該領域公認的做法寫的，而問法庫也是照這些做法寫的，所以對問法庫有利。「可以直接貼」那一項也偏向問法庫的格式。沒它那組照別的合理做法回答，也可能被判不及格。
- **工作資料夾是空的。** 兩組都看不到真的專案，回答的是「該怎麼做」，不是實際做完。
- **樣本小**：每題每組 2 次，只有一個模型（Opus 5.5）、一個評分模型家族（Claude）。
- **只測了 Claude Code。** Codex、Antigravity 上會不會叫用、效果如何，沒測。
- **沒有你的規則以外的干擾**：兩組都帶著這台的 `CLAUDE.md`（OmniKit 規則），這跟你平常的環境一樣。
