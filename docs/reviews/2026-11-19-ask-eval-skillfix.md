# 問法庫：改成「能重現的先修」之後重測（方向 4 的量法，2026-11-19）

Ryan 2026-11-19 定案（NOW.md 決定 1）：先改問法庫行為，再開方向 5。改法是工作資料夾裡能重現的情況先動手修，問法建議放最後；改完用方向 4 的量法重測 13 題訓練題。

## 結論

- **主要目標達到**：第一輪就修好從 5/26 升到 **13/26**，比沒裝問法庫（10/26）還多；修好率維持 26/26，平均 agent 輪數 2.04 降到 1.88（沒裝是 1.92）。
- **debug 與 ui 的反效果消失**：debug 第一輪就修好 3/10 → 8/10（沒裝 6/10），平均 1.8 輪 → 1.2 輪；ui 0/4 → 2/4，2.25 輪 → 1.5 輪，跟沒裝一樣。
- **沒完全達到的**：完成條件寫了「需求不清類的輪數不能變多」，結果 req-unclear 是 4.5 輪，比上次有裝的 4.0 多 0.5（兩次裡有一次多一輪），糾正一樣是 1.5，仍比沒裝的 5.0 輪、糾正 3.0 好。每題只有 2 次，這 0.5 輪在雜訊範圍內，但照實記成「沒有達到」。
- **新的退步：agent-notdone** 從 2.0 輪、糾正 1.0 變成 4.0 輪、糾正 3.0。讀對話（下面）的原因是：能重現不等於知道要修成什麼樣，新寫法讓 agent 在「規則只有使用者知道」時也直接動手猜。
- 建議：保留這次的改法（已 commit）。下一步只補一句「能重現、但『修成什麼樣才對』只有使用者知道時（計算規則、格式、取捨），先問一題再動手」，再用同一套 13 題驗證；不要拿保留題調。

## 改了什麼

`engine/skills/omnikit-ask/SKILL.md` 的「怎麼用」加成第 1 步：

> **能在工作資料夾裡重現的，先動手修。** 有錯誤訊息、測試會失敗、照步驟跑得出症狀、畫面看得到問題時，直接查、修、驗證，回報修了什麼。不要先教使用者怎麼問，也不要停下來問要不要動手；問法建議放在回覆最後，一兩句就好。缺的是只有使用者知道的東西（要什麼結果、偏好、取捨）才照下面的步驟先問。使用者明講只要問法時，給他「可以直接貼」的那一句就好。

原本第 4 步「先講你要怎麼做，再做」裡「只想要問法時給可以貼的那一句」移到第 1 步，其他步驟順延。

### 讀對話看到的

- **debug、ui 第一輪就動手了**：上次有裝時第一輪常先給「你可以直接貼這句」再問要不要動手；這次 debug-flaky、debug-recur、debug-side-effect、ui-missing-states 兩次都在第一輪修好。
- **agent-notdone 退步的原因**：題目是「你說全部價格都改成含稅了，結果購物車根本沒改好」，隱藏的需求是「每個品項含稅後四捨五入、只有總額照發票算法」。第 2 次對話 agent 第一輪就改、自己定了計稅規則，之後三輪各換一種四捨五入的猜法（還引用了營業稅法），每次都說「通過全部測試」，第四輪才問使用者要資料。症狀看得到，但「算對」的定義只有使用者知道；新的第 1 步把它當成「能重現」，直接衝了。
- **req-unclear 還是會先問**：兩次都在動手前問格式與欄位（回話種類有 answer），差的那一次是問完之後又被糾正一次。
