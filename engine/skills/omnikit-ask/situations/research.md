# 調研、比較、學習

共通點：agent 會順著你說、憑記憶答。補的是反方、來源、停止條件。

### 剛接手陌生的大專案
- 缺的是：看的順序。叫它「讀整個專案」只會得到膚淺的摘要。
- 做法：不改任何檔案。從設定檔、程式進入點、頂層資料夾看起；大範圍的搜尋交給子代理，只帶結論回來。交出：主要模組與相依關係、一個請求從進來到寫入資料的流程、本機怎麼跑測試、最值得先讀的 3 個檔案。
- 可以直接貼：「我剛接手這個專案，先不要改任何東西。請從設定檔與進入點開始，告訴我主要模組怎麼串、一個請求從進來到存資料經過哪裡、測試怎麼跑、最該先讀哪 3 個檔案。」
- 依據：官方的常見流程（先了解 codebase）。

### 懷疑自己一開始就問錯問題
- 缺的是：反方。模型傾向順著提問的人的前提。
- 做法：先用一句話重述使用者真正想達成的目的，指出有沒有把症狀當成原因、把手段當成目標。然後開新對話或子代理（沒看過這段討論），只給問題與方案，請它找出這個方案解錯問題的理由。有訂第二家模型時換一家審。最後回到主對話，由使用者決定要不要改問題。
- 可以直接貼：「不要預設我的問題定義是對的。先用一句話說出你認為我真正想達成什麼，指出我有沒有把症狀當原因。然後找一個沒看過這段討論的審查者，請它反駁這個方案。」
- 依據：紅隊與反方論證。官方：沒看過推理的審查者才有幫助，同一段對話裡自己反駁效果有限。

### 擔心改動引發連鎖反應
- 缺的是：具體的影響清單。抽象地「推演二階效應」容易空泛。
- 做法：先不實作。列出：誰讀寫這份資料或呼叫這個介面（搜尋程式碼，列檔名）、哪些測試涵蓋到、下游系統與人的流程會怎麼變、半年後可能累積的問題。標出最可能出事的一處，以及上線後要看哪個指標。
- 可以直接貼：「先不要實作。請列出這個改動會影響到的地方：哪些程式讀寫這份資料或呼叫這個介面、哪些測試涵蓋到、下游與人的流程怎麼變。標出最可能出事的一處，與上線後該看什麼。」
- 依據：系統思考的二階效應；官方的例子是「找出所有讀舊格式的地方」。

### 想從別的領域借解法
- 缺的是：把問題抽象成結構。直接問「有沒有類似案例」只會比對到表面的關鍵字。
- 做法：先把問題去掉領域用語，寫成結構與核心矛盾（例如「要快又要一致」）。找 3 個不同領域處理同樣結構的成熟做法，每個說明：保留了什麼結構、搬過來哪裡會不適用。調研時也用不含本領域字眼的一般說法去查。
- 可以直接貼：「請先把我的問題去掉領域用語，寫成結構與核心矛盾。然後找 3 個不同領域處理同樣結構的成熟做法，說明每個搬過來哪裡適用、哪裡不適用。」
- 依據：類比推理的結構映射；TRIZ。

### 調研只列幾個就停，還混進記錯的資訊
- 缺的是：停止條件與一手來源。
- 做法：不憑記憶回答。每個管道都查（官方文件、repo、社群），關鍵字從結果的新詞擴展，連續幾輪沒有新東西才停。星數、更新日期、授權要實際查並寫日期。分清楚「查證過的」與「待驗證的說法」。裝了 `omnikit-research` 就照它做。
- 可以直接貼：「請調查〔主題〕，不要憑記憶。官方文件、repo、社群都要查，查到連續幾輪沒有新東西才停。每個數字附來源與查詢日期，沒查證的標『待驗證』。」
- 依據：系統性文獻回顧；一手來源查核。

### 要用沒學過的技術，不想完全看不懂
- 缺的是：學習的節奏。預設會直接替你寫完。
- 做法：用使用者熟悉的東西類比核心概念。每寫完一小段，請使用者用自己的話解釋，或留一小塊關鍵的給他自己寫。Claude Code 可以切到 Learning 或 Explanatory 輸出風格。
- 可以直接貼：「我想邊做邊學〔技術〕。請用我熟悉的〔語言或框架〕類比核心概念，每寫完一小段就問我一題確認我懂，關鍵的地方留給我自己寫。」
- 依據：Anthropic 的實驗（2026-01）：用 AI 學新函式庫時，整個丟給它的人測驗分數低；同時問概念的人分數高。
