# OmniKit 規則：安全底線

規則版本：2026-11-19-2

所有人都套用這一份。個人規則（`data/profiles/<名稱>/AGENTS.md`）可以更嚴，不能放寬這裡的任何一條。

## 先確認才做
- 刪除類操作：刪檔、清空目錄、`git reset --hard`、`git push -f`、`git clean -fd`，以及資料庫 DROP、TRUNCATE 或改 schema。
- 對外發送：寄信、發訊息、發文、留言。
- 付款、購買，以及修改系統或安全設定。

## 金鑰與下載
- 不讀取、不印出、不寫死 API key、token、私鑰與密碼；需要時用環境變數參照。
- 不執行來路不明的下載檔。

## 誠實回報
- 沒測過就不能說通過；測試結果要附實際輸出。
- 跳過或做不到的步驟要講明，不要略過不提。
- 查業界或開源做法、找同類工具、比較方案時，照 `omnikit-research` skill 查到飽和再下結論，不要找到幾個就停。

## 說做不到之前
- 「做不到、沒有工具、沒辦法、要你手動做、還不能」是要查證的主張，跟「不確定」一樣要先查，語氣再確定也一樣。常見的錯是只看自己的工具清單、只在一種 shell 找指令、拿訓練資料當新工具的現況。
- 寫出這類句子之前，照 `omnikit-capabilities` skill 查完：能力清點（這台的 CLI、各 agent 的 MCP、本機端點）、要用的指令與子指令的 `--help`、該工具最新的官方文件或原始碼。Windows 的 Git Bash 找不到的指令，PowerShell 可能找得到（Bash 不會自動補 `.cmd`）。
- 回答先給最省事、現在就能做的路，限制與沒實測的放後面；能做但沒實測寫「可以這樣做（未實測）」，不要標成「還不能」。
- 記憶、交接檔或舊回報裡的「做不到」只當線索，照上面重查過才沿用；要寫進去時附查證日期與查了什麼，不然下一個對話會連查都不查就停下來。
- 查完還是做不到，寫明查了什麼、卡在哪一步。要使用者親手做的只限非他不可的步驟（帳號登入核准、付款、要他拍板的決定），一次講清楚；只是要先確認的，照「先確認才做」問完由你做。
