# OmniKeep 首頁：設計決定（第二版）

簡報不允許發問，以下是我替你做的決定。第一版（米白紙、墨、朱印）已整版換掉。

## 這版依據的回饋
- 「偏好深色 iOS 官網風格，參考 apple.com.cn/iphone-18-pro」：改成黑底、大標置中、產品畫面當主角、分頁切換展示，不用設計類 skill。
- 「大部分螢幕是 1920×1080」：桌機改以 1920×1080 檢查，第一屏要在這個尺寸下好看；手機以 390 寬檢查。
- 「不要示意畫面、不要 agent 自己挑的示範內容」：頁面上所有產品畫面都換成 Ryan 指定那批真實截圖（`C:\Users\user\.omnikit-wp1-demo\screens\`，15 則收藏、OmniKeep 深色主題、1920×1080）。我自己畫的手機、聊天泡泡、蔥油餅逐字稿、搜尋示範、迷你卡片全部拿掉。

## 設計方向
- **黑底、內容在前**：底色純黑，區塊交替用 `#000` 與 `#0D0D0E`；卡片 `#141416`／`#1D1D1F`。文字分四級灰（`#F5F5F7` 到 `#6E6E73`）。
- **一個重點色**：沿用第一版定的橘紅（`#FF6A3D`，漸層到 `#FFC48A`），只用在大標的關鍵字、小標、截圖後面的光暈。
- **字型**：系統字優先（Mac 上是 SF Pro／蘋方），其他平台用 Inter 與 Noto Sans TC；指令與網址用 JetBrains Mono。
- **截圖放在視窗框裡**：深灰邊框、頂端三個圓點與網址列。網址寫 `127.0.0.1:5000`，是 README 說的本機開啟位址。

- 這批截圖沒有 Telegram 對話。Telegram 是 README 說的主要入口，所以收錄區仍然用最大的卡片講 Telegram，但卡片裡只有文字和一個紙飛機線條圖示，不畫假的對話畫面。

## 內容決定（沿用第一版，已重新對過 README）
- 結構：一句話 → 三步驟 → 收錄 → 讀取 → 找得到 → 資料在自己手上 → 實驗功能（標明「還會改」）→ 三分鐘開始用 → 常見問題 → GitHub。
- 三步驟第 1 步多寫一句「在電腦前，就按頂部的『新增』貼上」，因為配圖是「新增」面板（README：按頂部的「新增」，快捷鍵 N，把連結貼上）。
- 安裝指令照 README 原文；複製按鈕只複製指令那一行。依訪客的作業系統預設顯示 Windows 或 macOS、Linux 分頁。
- 沒有任何數據、使用者評價、合作夥伴或媒體 logo。截圖卡片上出現的 GitHub star 數是那些專案頁面的原始內容，不是 OmniKeep 的數據。

## 互動
- 讀取區與找得到區的分頁可以點，也可以用左右方向鍵切換。
- 捲動時區塊淡入；開了「減少動態效果」時不播動畫，內容直接顯示。
- 沒有 JavaScript 時，每個分頁組只顯示第一張截圖，其他內容照樣看得到。

## 檢查結果（2026-11-19）
- 在 `site/` 用 `python -m http.server 18803` 開 http://127.0.0.1:18803/，在 Chrome DevTools 檢查：
  - 1920×1080：`scrollWidth` 1905 等於 `clientWidth` 1905（差的 15px 是捲軸），沒有橫向捲動。15 張圖全部載入成功。console 沒有錯誤，只有一則 Chrome issue 提示「Lazy-loaded images should have explicit dimensions」；每張 lazy 圖片都有 `width`／`height` 屬性，判斷是 Chrome 對 `<picture>` 的提示。
  - 390×844（行動裝置模擬，DPR 2）：`scrollWidth` 390 等於視窗寬，超出右邊界的元素 0 個；手機版改用局部圖（inbox-m、detail-yt-m、ask-m 等）並確認有載入。大標都是兩行，沒有單字掉到下一行。
  - 分頁：點擊與方向鍵都會切換，對應的面板會顯示或隱藏。
  - 首屏傾斜效果：在頂端時 `rotateX(10deg) scale(0.94)`，捲到 700px 時 `rotateX(0deg) scale(1)`。
- 沒測：Safari、Firefox、實體手機、1440 等其他桌機寬度，以及 Google Fonts 載入失敗時的備用字型。
