數下面四項，回覆裡有幾項是明確建議要做或說明接下來會照著做的：(1) 明確先不改動程式碼、不合併也不部署，只做檢查；(2) 實際執行型別檢查、lint、測試與建置並要求貼出實際結果；(3) 清查這批改動的高風險項目（如新增環境變數、寫死的網址、破壞性資料庫變更、被吞掉的錯誤等）；(4) 最後給出明確的「可以上」或「不行」結論以及具體的阻擋項目。回覆先問 1 到 3 個關鍵問題並說明之後會照這些步驟做，也算做到；不要求措辭一模一樣。PASS 如果有三項以上。FAIL 如果少於三項，或只給泛用的上線注意事項（例如「記得備份、找人 code review」）、或直接建議先合併看看。
