## 開場
`users` 表的 `full_name` 欄位要拆成 `first_name` 跟 `last_name`，而且不能停機、也不能讓舊資料不見。現在 API 跟寄電子報的排程都有讀這張表，這要怎麼改才不會出事？

## 處境
你是這個會員系統的負責人，懂一點資料庫但不會寫程式。行銷要在電子報開頭寫「親愛的 小明」，所以要把姓名拆開。

## 想要的結果
- 資料表多出 first_name（名）、last_name（姓），舊會員的資料都要拆好，一筆都不能少。
- 舊的 full_name 先留著，現有的 API 跟電子報排程照常能跑。
- 新註冊的會員也要有 first_name、last_name。
- 姓名怎麼拆：中文名第一個字是姓、後面是名；複姓（歐陽、司馬、諸葛、上官）兩個字都是姓；英文名用空白分開，最後一段是姓、前面是名；只有一個字或拆不開的，整個放在 first_name、last_name 留空。
- 照專案平常的方式加 migration（`python manage.py migrate`）。

## 細節
- 會員大約 12 萬筆，大多是中文名，少數英文名。
- 有幾位會員姓歐陽、司馬。
- 電子報排程每天早上 6 點跑。
